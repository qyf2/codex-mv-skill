# 歌曲 MV · Codex

把歌曲、故事和角色变成可编辑的手绘动画工程，并交付经画面检查的 MP4。
使用随附 p5.js + p5.brush 引擎在 Chrome/Chromium/Edge 中逐帧绘制，以 FFmpeg 编码。
不需要 Claude、图像生成服务、视频生成服务、API key 或其他 skill。
Clawd 是上游引擎的可选示范角色，不代表 Codex，也不限制用户角色选择。

## 定位与运行

从当前被加载的本文件位置推导 skill 根目录 `<SKILL>`；不要假定安装在 `~/.claude`、`~/.codex` 或固定盘符。
所有脚本参数按独立参数传给 shell；Windows 为含空格的路径加引号，命令示例使用 PowerShell，POSIX 使用相应引号。
不要从 GitHub 临时拼装遗漏的引擎文件；完整模板就在 `assets/template/`。

```text
python "<SKILL>/scripts/new_project.py" "<PROJECT>" --duration=15
```

进入 `<PROJECT>`，执行 `npm ci` 和 `node doctor.mjs`。详细依赖、平台命令和排错见
[运行与渲染](references/runtime.md)。需要 Python 3.10+、Node.js 22.12+、浏览器、FFmpeg；
只有自动节拍分析需要 `requirements.txt` 中的 NumPy。先检查已有环境，再安装缺少的部分。
doctor 必须报告浏览器 WebGL2 可用；无硬件 GPU 时尝试 `--soft-gl` 并报告测得的速度。

在设计第一镜头前通读项目里的 `ANIMATION_GUIDE.md`，了解 `paint`、`clawd`、表情和时间函数。
该指南保留上游绘制 API；本 skill 与 references 对安装、歌词和渲染的说明优先。
需要角色模型参考时，渲染 `emotions` / `views` 循环并用当前环境的图片查看工具检查。

## 素材与创意

先检查用户已给出的音频、LRC、时间范围、时长、角色、故事、画幅、字幕要求和输出位置。
已有答案不重复问。需要创意补充时，把故事、情绪、反复意象和避用元素合成一个简短自然问题；
这些偏好可留空，届时按歌曲提出合理方案。继续处理不依赖答案的素材检查。

- 有音频：实际解码/探测时长和可用片段，保留原文件。剪辑统一使用歌曲时间减去片段起点。
- 歌词 MV：优先使用用户的 LRC。没有时间轴时，请求其提供，或在用户允许转写后使用当前真实可用的转写工具。
  不编造歌词和词级时间。等待素材期间仍可写视觉方案。
- 用户明确不要歌词时，继续制作无字幕 MV；不要强制要求 LRC。
- 只有基本 LRC 时，说明行起点准确而行内高亮为近似。要求精确逐字时需要增强 LRC 或经核验的词级对齐结果。
- 未提供音频时可完成分镜、动画预览，但不能称为已完成音画同步成片。
- 使用用户有权使用的素材；不自动搜取商业歌曲。示例没有附带商业音频。

歌曲处理、歌词转换、增强 LRC 格式与节拍相位见 [音乐与歌词](references/music-video.md)。
保存 `assets/beat-grid.json`，并试听/检查强拍；检测结果只是估计，慢歌可能用半速节拍。

## 分镜与工程

先创建 `STORYBOARD.md`，包含：一句话故事、世界与色彩变化、角色与情绪弧线、反复意象、
歌曲/片段时间映射，以及镜头表（起止时间、对应歌词/乐句、事件、反应、镜头、转场）。
每镜头写观众依次理解的要点及其时间，避免一行歌词塞入太多事件。结尾呼应开头。
把分镜简明展示给用户；用户已要求直接完成时继续实现，避免额外设置必经审批点。

- `src/config.js` 的 `PROJECT` 保存 `duration`、`bpm`、`offset`、`fps` 和 `audio`。
  `offset` 是片段中第一个选定强拍的秒数，不是 LRC offset。
- 每场景一个 IIFE 文件，调用 `shots([[t0, fn], ...])`，在 `studio.html` 按顺序加载。
  替换 starter/demo 的脚本标签，不能同时保留原镜头与新镜头。
- 先画关键姿态并检查，再补动作；复用同一角色、道具、色板，保持方向与比例一致。
- 用 `paint()` / `inkLine()` 保持手绘感；发光用 `glow()`；转身用画好的 key views。
  除歌词和用户明确需要的内容外，避免堆叠文字解释故事。
- 帧必须是时间 `t` 的纯函数：不能依赖上一帧、累积物理、计数器或 `Math.random()`。
  稳定随机用 `hash`，独立物体先调用 `boilSeed(key)`。
- 角色要足够大、表情有过渡、动作有预备与收势；镜头间有明确衔接。
- 长片按乐章分文件，保持共享角色 API 稳定；本 skill 不要求启动子代理。

可以参考 [完整上游分镜与场景示例](examples/xiaozhen/STORYBOARD.md)，但不要复制其歌曲、故事或歌词作为新作品。

## 逐镜头画面验证

从项目目录运行小范围预览：

```text
node render.mjs --sheet=0.2,0.8,1.5 --cols=3 --w=480 --out=out/check/shot-a.jpg
node render.mjs --strip=1:1.25 --w=320 --out=out/check/motion-a.jpg
node render.mjs --sheet=1.2 --crop=700,350,520,450 --w=520 --out=out/check/face-a.jpg
```

用真实图片工具（例如 `view_image` 或当前宿主的图片查看能力）打开图，不能只读代码、日志或文件名。
每镜头至少检查一组关键帧，每个关键动作和接缝检查连续帧，剧情重要的脸/手/道具检查局部。
重点检查叙事可读性、接触位置、画面连续、转场、字体缺字、字幕安全区，以及歌词显示和歌声是否对齐。
发现问题修复后重新渲染受影响的预览。见 [审片与交付](references/review.md)。
图片工具不可用时如实标注尚未视觉审片，不能声称画面已通过。

## 成片与交付

沿用用户已选择的执行地点。在 Codex 桌面本地 shell 中渲染属于本地渲染；
不要把所有代理执行都称作云端。云环境中若长片耗时、预算或执行地点尚未确定，
用少量帧的实测耗时给出估计，询问必要的选择；已有明确授权则继续。
用户选择本地后，不转到云端全量渲染。需要其机器执行时提供对应系统的完整命令。

```text
node render.mjs --frames --workers=2
node render.mjs --encode --out=out/video.mp4
```

渲染和编码两次调用必须保持相同的 `--fps`、尺寸、`--loop`、GPU 模式和 `--frames-dir`。
长片先实测 3–5 帧，估计总帧数和耗时；软件 GPU 通常先用单 worker。
渲染缓存按源码/资源/设置的内容指纹分目录，改动代码会生成新缓存。不要搬旧帧冒充新帧。
中断后同参数重跑会补缺帧；编码会拒绝缺帧，不应把编码失败报告成成功。
默认读取 `PROJECT.audio`，`--audio=` 可覆盖，`--no-audio` 明确关闭。

最后验证 MP4 存在、可解码、有预期音轨、时长/尺寸/帧率正确，并实际抽查首尾和歌词关键时刻。
交付 MP4、可编辑工程、分镜、歌词/节拍数据、预览图、复现命令和简短的已验证/未验证说明。
在桌面应用中用绝对路径提供文件和本地视频预览；其他环境使用其支持的附件方式。
